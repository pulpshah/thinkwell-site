Signed in, the capsule always shows three icons: the logo, search, and the menu. While recording the menu lines turn a quarter turn and become the waveform. Geometry follows the Figma frame: 32 wide, 66 tall, icons 16, gap 10, end padding 12, side padding 8. The extended form adds one slot for the transcript and grows to 92. Position is x and y as percent of free travel; the OS bar is excluded from free travel. Docked edge and orientation are derived, never stored.

Needs attention, by urgency

Keys 1 to 9 and 0 step through the states. Low breathes slowly, medium breathes faster and deeper, high blinks the whole rim twice every 1.6 s. Clicking the capsule while it needs attention opens the explanation instead of the menu.

Speakers

Colors are assigned from a palette that stays clear of Thinkwell pink and amber and separates for red-green color vision. Each can be changed per person.

Playback cues

Interruption: the newcomer's light appears a tenth of a lap behind the speaker and closes at twice the tempo. The moment it passes, it takes the lap and the speaker's light eases out behind it. Nobody snaps, nobody stops; the floor changes hands by passing. Crosstalk fires two. Laughter: the light skips twice and warms toward white. Both fire on their own in the simulation.

Audio

Voice moves brightness and tail length a little in the speaking states, and moves the waveform icon. It never changes speed.

Model

Three nouns. A module is a unit of content and behavior (search, player, transcript). A card is a module mounted in the UI, white, rounded. A tray is the gray container that holds one or more cards, with a chrome row above it (pin on the left, actions on the right). Linked means cards share a tray; unlinked means a card has a tray of its own. The main tray is anchored to the capsule; every other tray floats and is dragged by its chrome row. The chrome row holds pin and expand only; New recording lives in the search field, once.

capsule (shader) ──click──▶ tray(main) ─┬─ card(search)      always here, cannot unlink
                                 ├─ card(video)       optional
                                 ├─ card(player)
                                 └─ card(transcript)
                       tray(free) ─── card(transcript)  after unlink; drag back to relink
full screen (later) = the same cards in a different layout container

Full screen is not a new product. It is a layout container that arranges the same cards in a grid. Nothing in a module knows which container it is in; it only knows its box and the bus.

Module contract

Every module is a plain object registered with registry.define. The shell owns the card frame, the header, link and unlink, tooltips, persistence and the bus. The module owns only its body.

registry.define({
  id: 'transcript',            // unique, stable, used in storage keys
  title: 'Transcript',         // fallback header text
  icon: 'transcript',          // sprite id for chips and menus
  canUnlink: true,             // false only for search
  grow: true,                  // takes the free height in a tall tray
  prefHeight: 520,             // px, a hint for the container, never a rule
  mount(body, ctx) {},         // build DOM inside body once
  update(ctx) {},              // cheap re-render on state change
  unmount() {},                // release timers and observers
  onEvent(type, payload) {}    // bus messages it listens to
});
ctx = { state, bus, tip, toast, copy, fmtTime, card, tray }

Rules the shell enforces: a module never touches another module's DOM; it emits and listens on the bus. A module never positions itself; it fills the card. Anything that changes size does so inside its own card, and the tray reflows by transform, not by animated height. Text the user might copy is real text, never canvas.

Modules

Search

A command menu. Results come in groups, each sorted by relevance (whole word, then prefix, then substring): In this recording (live lines while recording, the transcript once loaded), Recordings, People, Actions. Open existing browses recordings and actions with an empty query. The field's one action is New recording, which becomes Stop while recording. Enter or click loads the recording into player and transcript. When a recording is loaded the same field searches inside the conversation, the transcript marks matches and scrolls to the first, and the field keeps one action, Open another recording. Production: Algolia for text plus vector search; this file uses a local filter with the same result shape.

Video

Optional card. Source is either the meeting video or a clip referenced in the transcript; the label in the corner says which. Controls: play, back 15, forward 15, mute, captions, full screen, more. It follows the player's clock over the bus, so seeking in either moves both.

Play and pause also drive the capsule: the pill light shows Playing in the color of whoever is speaking at the playhead, and Paused when stopped. Double click on the capsule pauses and resumes, so both surfaces agree.

Player

Title (truncates at the card width), speaker line, three chips that show or hide transcript, speaker markers and snapshots. Waveform bars are real elements so they can be styled and hit-tested; played bars dim. Speaker markers sit above and below the waveform at turn changes, colored per speaker, tooltip on hover, click to seek. Progress rail with the pink playhead, drag or click to seek, arrow keys nudge by 5 s.

The tutorial

Interactive tutorial is the first-run experience: eleven short steps in plain words, each waiting for the user to do the thing and advancing when it sees it done, with Show me to have it done for them and Skip at every step. It covers open, search, record one voice, stop and save, record two voices, rename a speaker, stop, comment, the menu, and close. It ends in under five minutes with the user's own recordings in the list. The escape hatch never disappears.

The tour

Play the tour runs the product for about four minutes and narrates it. Nothing in it is staged: the ghost cursor moves to the real control and the same function the user would trigger is called. Order: the capsule and its hover; the menu; search as a command menu; a solo recording (15 s); two speakers with a voice resolving from Speaker 2 to a name (18 s) and a speaker renamed by hand; the room with four voices, an interruption and a ticker (25 s); playback following the transcript; search inside the recording; a comment with an @ mention; the chart from the ticker and an annotation; more blocks; unlink, pin, relink; closing cards; the window; settings; hide and restore. Stop at any time; 2x halves waits and doubles the recording clock. It is also the developers' blueprint: each step is one function call they can find by name.

Recording, live

Double click the capsule (or New recording anywhere) and a Recording card appears at the top of the tray: a soft pulse, the running clock, and a listening indicator until the first line lands. Lines arrive as people speak, grouped by speaker with the voice-match mark, newest always in view. The capsule follows: the light takes the current speaker's color, the menu icon has become the waveform. Search in this state searches the live lines first. Stop from the card, the menu or a double click; the card turns to Processing, then the finished recording opens in its place with player, transcript and the summary toast.

Settings

The user-facing switches as a card, opened from the menu, search, or the window: capsule silver or dark, tray look, time display, 24 hour, speaker colors, tooltips, hover, cues. The developer panel keeps everything else.

Stock

Opens when the user wants it: a ticker mentioned in the transcript is underlined, click it and the chart card arrives above the player. Prices, spread, volume, a candle chart with volume drawn as one SVG, ranges from 1D to All, an OHLC readout under the pointer, and Annotate to drop a note at a candle (labeled with the playhead time). Production swaps the mock candles for a market data feed; the card shape stays. Colors here are data colors and appear nowhere else.

Transcript

Chunked by paragraph inside speaker blocks. Each line has a timestamp in the chosen time mode (start, end, real, with a 24 hour switch), the text, and a copy button on hover. Copy message copies sender, timestamp and message. Selecting text shows a Copy text bubble that copies only the selection. The current line follows playback; scrolling away pauses following until the user clicks the current line again. Snapshots strip appears under the block that owns them. Lines are real text with content-visibility so long transcripts stay cheap; above roughly 800 lines the production build should virtualize.

Performance

Measured live: frames longer than 16.7 ms during the 1.2 s after any input, and the worst frame. Budgets: open and close under 320 ms with zero long frames; typing in search under one frame per keystroke; scrolling a 2 hour transcript at 60 fps; DOM under 1,500 nodes with everything open.

  1. Cards are laid out by the browser once; reorders animate transform only (FLIP). No animated height, width, margin or box-shadow anywhere.
  2. The transcript uses content-visibility: auto per block so off-screen blocks cost nothing to paint. Production virtualizes above roughly 800 lines.
  3. Search runs on input with results built once per keystroke; nothing is rebuilt that did not change.
  4. The player clock is a single requestAnimationFrame that moves one knob and one scaleX; ticks to the bus are throttled to 8 per second.
  5. One shared tooltip element, one popover element, one selection bubble. No per-control instances.
  6. The tray is will-change: transform only while open; free trays being dragged run with transitions off.

Persistence

One key, tw-shell, one JSON object: which tray each module is in and its order, each free tray's x and y, pin per tray, tall, time mode, 24 hour, chips. Written on change, read on start, validated against the registry so a removed module never breaks load. Electron port: electron-store, same shape.

For the port

  1. Own BrowserWindow: frame: false, transparent: true, alwaysOnTop: true, hasShadow: false, webPreferences.backgroundThrottling: false. The capsule window is the square wrapper; the tray is a second frameless window positioned from the same x, y model, minus the work area insets Electron reports in screen.getPrimaryDisplay().workArea.
  2. Shader draws shadow, body, rim, sheen and up to three lights. DOM draws the icons, tooltips, right-click menu, attention modal and every card in the tray. Only transform and opacity animate in CSS.
  3. Hide maps to a Tray in Electron on both platforms (status item on macOS, notification area on Windows). The tray click restores; the tray menu is the same right-click menu.
  4. IPC surface: setState, setSpeaker, setAmplitude, cue, setAttention, setOption, setSize, setForm, setTheme, setPlatform, setHidden, setPosition(x, y), setBackground('dark' | 'light'), setTucked.
  5. Re-run resize() when devicePixelRatio changes so the rim stays one physical pixel on every display.
  6. Electron 44: this file is two scripts (capsule, shell) with no build step and no dependencies. The capsule becomes its own transparent BrowserWindow; the tray and the main window each become a BrowserWindow with the same DOM and CSS. Tokens live on :root and .stage[data-tw-theme]; the bus becomes the IPC channel with the same event names. Keep the DOM ids: the design system's selectors depend on them.
  7. Power: when nothing moves the loop drops to about 4 fps and the readout says idle; any input wakes it for an immediate frame. Keep both in the port.

What comes next

  1. Full screen: a second layout container that takes the same cards and arranges transcript left, player and video right, search on top. The contract already forbids anything that would break this.
  2. Stock chart and AI chat as cards: define, mount, listen for player.tick and search.query. Nothing else to touch.
  3. Real data: Deepgram and Cobalt transcripts map to speaker blocks and lines with start and end; Algolia results map to the result shape used here.
